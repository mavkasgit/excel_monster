# Правила оформления коммитов

## Структура коммита

Каждый коммит должен иметь следующую структуру:

```
<тип>(<область>): <короткое описание>

[<длинное описание>]

[<футер>]
```

### Тип

-   **feat**: Новая функциональность
-   **fix**: Исправление ошибки
-   **docs**: Изменения в документации
-   **style**: Изменения, не влияющие на логику кода (пробелы, форматирование, и т.д.)
-   **refactor**: Рефакторинг кода, без изменения его поведения
-   **perf**: Улучшение производительности
-   **test**: Добавление или изменение тестов
-   **chore**: Другие изменения, не связанные с исходным кодом или тестами (например, изменения в файлах сборки)

### Область (scope)

Область коммита - это необязательное поле, которое указывает на часть проекта, которую затронули изменения. Например, `Module1`, `ModuleForm`, `Rules`.

### Короткое описание

Короткое описание должно быть лаконичным и отражать суть изменений.

### Длинное описание

Длинное описание - это необязательное поле, в котором можно более подробно описать изменения.

### Футер (footer)

Футер - это необязательное поле, в котором можно указать `BREAKING CHANGE` или ссылки на задачи (issues).

## Пример

```
feat(ModuleForm): Добавить кнопку для закрытия формы

Добавлена кнопка "Закрыть", которая выгружает форму из памяти.

Closes: #123
```
